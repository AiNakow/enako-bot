## 归档条件

归档前应满足：

1. 按已确认范围完成实施及对应验收，并留下可核对的结果或用户明确的完成确认；或已有明确的范围调整／终止结论，记录未实施和未验收项的处理方式。
2. 在文档顶部注明最终状态、关闭／归档日期和剩余限制。终止或取消应如实标注，不写成已完成。
3. 验收结果标明来源、环境、日期、实际覆盖率及未执行原因；以用户确认为依据时，记录确认日期和来源，未提供的测试细节不推测。历史本地测试结果与后续真实环境完成确认分别保留；已明确不属于该次范围的事项保留排除说明。
4. 计划与对应验收记录互相链接，迁移后同步更新全部引用。每份文档只保留一个正文位置，不在进行中目录保留副本。

代码实现完成但整体验收未闭环，或尚未找到完整的完成证据时，继续保留在 `in-progress/`；新方案尚待确认时保留在 `pending-confirmation/`。归档操作本身不改变业务范围，也不表示任何部署已经得到授权或已经执行。
