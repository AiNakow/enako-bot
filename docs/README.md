# 文档索引

按文档状态和用途分类。**代码已实现不等于整个计划和验收已经闭环**；仍有未执行事项或完成状态待核实的文档保留在进行中目录。

## 目录约定

```text
docs/
├── README.md                    # 统一入口、文档状态和分类规则
├── pending-confirmation/         # 待用户确认、尚未开始实施的方案
├── in-progress/                 # 进行中分类，当前无文档；有新实施任务时使用
│   ├── plans/                   # 已开展但实施／验收尚未闭环的计划
│   └── acceptance/              # 分阶段验收及仍有未执行项的验收记录
├── archive/                     # 实施与验收已闭环或已明确终止的历史文档
│   ├── plans/                   # 已完成的历史方案
│   └── acceptance/              # 已完成的验收记录
├── examples/                    # 当前配置示例，保留既有使用路径
└── schemas/                     # 当前机器可读约束，保留既有使用路径
```

分类规则：

- 待确认方案：标注建议和待确认项；确认范围并开始实施后，移动同一文件到 `in-progress/plans/`。
- 进行中计划：注明已完成部分、未执行事项和待核实状态。代码已经实现但验收尚未结束，仍属于进行中。
- 进行中验收：区分通过、失败、未执行和待核实；历史通过结果保留原日期与覆盖率，不因目录调整更新成新结果。
- 归档：计划与验收已闭环，或范围调整／终止已有明确结论后才归档。核实不到完成证据时，不推定已经完成；关闭状态以当时确认的范围为准，排除事项需有明确记录。
- 文档移动后同步更新索引、相互引用和项目 README，不保留多份并行正文。计划与验收记录使用链接关联。
- 示例和 Schema 仍是现行配置资料，不随方案状态迁移。
